# Web 工作台第一阶段原型

## 目标

第一阶段交付了一个高保真工作台；第二阶段已将相同界面接入真实 LegacyPilot REST API。工作台不再使用内置任务数据。

核心产品形态是“对话式任务入口 + 运行工作台 + 源码证据”，而不是通用聊天应用。

## 本阶段范围

- 三栏布局：任务导航、Agent 工作区、源码证据。
- `EXPLAIN`、`ANALYZE`、`CHANGE` 三种自然语言任务入口。
- 从真实后端读取 Banking Demo 项目和任务。
- 展示真实 checkpoint、执行计划和运行进度。
- 模式对应的结构化结果。
- 点击结论查看路径、符号、行号、代码摘录和 revision。
- `CHANGE` 模式的真实独立审批与恢复运行。
- 从后端数据库恢复项目、任务和最近一次运行状态。
- 桌面、平板和窄屏响应式布局。

## 非目标

- 不实施 OIDC 登录。
- 不实现无限多轮聊天。
- 不提供完整代码浏览器和设置中心。
- 不提供源码全文读取；当前只显示 artifact 内经过验证的摘录。

## 验收路径

1. 打开工作台，默认看到已经完成的 `ANALYZE` 任务。
2. 点击不同结论，在右侧核对源码证据。
3. 切换到 `EXPLAIN`，看到不同的结果结构。
4. 切换到 `CHANGE`，使用独立审批人身份完成真实审批并恢复运行。
5. 新建任意模式任务，观察计划逐步执行并生成结果。
6. 刷新浏览器，任务从后端数据库重新加载。

## 已完成的第二阶段接入

- 从 `GET /api/v1/projects` 和项目任务列表读取真实导航数据。
- 创建任务、创建 run，并通过幂等命令异步受理统一执行；浏览器请求结束后后台任务继续运行。
- 每 2.5 秒读取生命周期、checkpoint、report 和 artifact。
- 将结构化产物和源码证据映射到工作台结果区。
- 从服务端读取审批摘要，以独立审批人 JWT 提交决定，并按 action digest 幂等地异步恢复运行。
- API 错误显示稳定错误信息和 correlation ID。
- JWT 仅存放在当前标签页的 `sessionStorage`，不写入长期浏览器存储。

安全源码全文读取接口尚未实现，因此证据面板只显示 artifact 中经过验证的摘录。

## 本地运行

推荐的完整演示入口：

```bash
./deploy/demo/start.sh
```

它会连接真实本地模型、初始化 Banking Demo 和临时演示身份。单独开发前端时再使用以下命令：

```bash
cd apps/web
npm install
npm run dev
```

开发服务器会把 `/api` 代理到 `http://127.0.0.1:8080`。也可以在连接设置中填写 API 地址，或在构建时设置 `VITE_API_BASE_URL`。跨域部署需要在同源反向代理或后端允许的 CORS 策略下运行。

生产构建：

```bash
npm run build
```
