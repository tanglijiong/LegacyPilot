# LegacyPilot v0.1 产品需求文档

**状态：** Draft
**目标版本：** v0.1 Vertical Slice
**产品定位：** 面向企业存量 Java 系统的可验证智能研发 Agent

## 1. 背景与问题

企业 Java 项目的改动成本通常不在“写几行代码”，而在理解陌生代码、识别隐含调用关系、控制变更范围，并证明修改没有破坏原有行为。

通用 Coding Agent 在企业场景常见以下缺口：

- 上下文选择只依赖向量相似度，容易遗漏调用链和结构关系。
- 工具权限过大，可能在宿主机任意读写或执行命令。
- 修改过程不可审计，失败后难以恢复或解释。
- 只生成代码，不把编译、测试、静态分析和风险评估作为完成条件。
- 缺少可重复的评测集，无法证明成功率、成本和改进效果。

LegacyPilot 将“代码理解 + 受控执行 + 自动验证”作为一个整体问题解决。

## 2. 产品目标

v0.1 要证明一件事：

> 给定一个陌生的 Maven/Spring Boot 项目和一条明确需求，单个 Agent 能在受控环境中完成影响分析、生成计划、修改代码、执行验证，并产出可审计报告。

目标不是替代开发者，而是把开发者从重复检索和验证工作中解放出来，同时保留关键决策的人工控制权。

## 3. 目标用户

### 3.1 主要用户：维护存量系统的 Java 开发者

- 需要快速理解不熟悉的模块和调用链。
- 需要处理小到中等规模、验收条件明确的需求或缺陷。
- 希望获得变更建议，但不能接受 Agent 在宿主机无限制执行。

### 3.2 次要用户：技术负责人或 Reviewer

- 关心 Agent 为什么修改这些文件。
- 需要查看验证证据、失败过程、风险和残留问题。
- 希望比较不同模型或策略的任务成功率和成本。

### 3.3 开源使用者：Agent / Java AI 工程师

- 希望复用 Agent Runtime、MCP 工具或 Eval 框架。
- 希望接入不同 LLM、检索器、沙箱和观测后端。

## 4. 核心使用场景

### 场景 A：实现小型业务需求

用户导入一个 Maven 项目，输入需求与验收条件。系统分析相关 Controller、Service、Repository、Entity 和测试，生成变更计划。用户批准后，Agent 在隔离 worktree 中完成变更并验证。

### 场景 B：修复可复现缺陷

用户提供缺陷描述和失败测试或复现命令。系统定位代码、提出修复方案、生成补充测试，并以失败测试转为通过作为主要证据。

### 场景 C：只做影响分析

用户要求系统不改代码，只输出受影响组件、调用链、候选文件、风险和建议测试范围。

## 5. 端到端用户流程

1. 用户通过本地路径或 Git URL 注册目标 Java 项目。
2. 系统检查项目类型、构建工具、Java 版本和安全前置条件。
3. 系统在独立 worktree/工作目录中建立代码索引。
4. 用户创建任务，输入需求、约束和可选验收命令。
5. Agent 使用结构检索与文本检索构建相关上下文。
6. Agent 输出影响分析、变更计划、预计修改文件和风险等级。
7. 需要写文件或执行高风险命令时进入审批门。
8. Agent 执行工具、观察结果，并在预算内修复失败。
9. 验证器执行编译、测试、静态分析和 Git diff 检查。
10. 系统输出报告；用户决定接受补丁、继续迭代或丢弃 worktree。

## 6. v0.1 功能范围

### 6.1 项目接入与检查

- 支持本地 Git 仓库和公开 Git URL。
- v0.1 仅正式支持 Maven 单体或多模块 Java 项目。
- 检测 `pom.xml`、Java 版本、模块列表和测试框架。
- 不直接修改用户原工作区；每个任务创建独立 Git worktree。

### 6.2 Java 代码理解

- 使用 JavaParser 提取类、方法、字段、注解、继承、实现和导入。
- 识别常见 Spring 角色：Controller、Service、Repository、Entity、Configuration。
- 建立文件、类型、方法和基础调用/引用关系。
- 保存符号位置，使检索结果可以回到准确文件和行号。

### 6.3 Hybrid Code Retrieval

- 支持精确符号搜索、文本/BM25 搜索和可插拔向量搜索。
- 根据依赖图扩展上下游节点，而不是只返回相似文本片段。
- 根据任务预算裁剪上下文，记录每段上下文的入选原因。
- v0.1 允许向量检索关闭；关闭后仍必须能用 AST + BM25 完成基线任务。

### 6.4 自研 Agent Runtime

- 实现 Plan → Act → Observe → Verify → Retry 循环。
- 维护持久化任务状态、步骤、工具结果、预算和终止原因。
- 支持最大步骤数、最大重试数、Token/成本和运行时长预算。
- 支持暂停、批准后继续，以及进程异常后的安全恢复。

### 6.5 工具系统

v0.1 至少提供：

- `read_file`
- `search_code`
- `find_references`
- `create_patch` / `apply_patch`
- `git_diff`
- `compile_project`
- `run_tests`
- `run_test_class`
- `static_analysis`

所有工具必须声明输入模式、输出模式、风险等级、超时和审计信息。

### 6.6 安全与审批

- 工具默认无权访问任务 worktree 之外的路径。
- 命令执行使用参数化命令和白名单，禁止任意 shell 字符串直通。
- 读操作可自动执行；写操作和命令执行按策略审批。
- 凭证通过环境变量或本地配置引用，不写入 Trace、Prompt 或报告。
- 网络访问默认关闭；如模型调用必须联网，只允许模型适配器访问配置的端点。

### 6.7 自动验证

- 验证 Git diff 只包含允许的工作区文件。
- 运行 Maven compile/test；按项目配置运行 Checkstyle/SpotBugs。
- 收集测试数量、通过/失败、覆盖率（可用时）和静态分析结果。
- 只有必需验证项全部通过，任务才可标记 `SUCCEEDED`。

### 6.8 报告与观测

- 输出机器可读 JSON 报告和人类可读 Markdown 报告。
- 报告包含计划、影响组件、修改文件、验证证据、风险、未解决项。
- Trace 包含 Agent 步骤、工具调用、耗时、Token、估算成本和错误。
- 敏感信息必须脱敏；源代码正文默认不进入长期 Trace。

### 6.9 MCP 与 Eval 最小闭环

- 提供一个只暴露只读项目能力和 Maven 验证能力的最小 MCP Server。
- 提供至少 5 个固定 Eval 任务及可重复的执行命令。
- 输出任务成功率、编译成功率、测试通过率、平均步骤、Token、成本和时长。

## 7. 用户故事与验收

| ID | 用户故事 | 验收条件 |
| --- | --- | --- |
| US-01 | 作为开发者，我想导入陌生 Maven 项目 | 系统识别模块、Java 版本并建立可查询索引 |
| US-02 | 我想知道一个需求影响哪些代码 | 报告列出候选文件、调用链、理由和置信度 |
| US-03 | 我想先审计划再允许改码 | 未批准前不能写文件或运行受限命令 |
| US-04 | 我想让 Agent 自动完成小改动 | 修改仅发生在任务 worktree，过程可追溯 |
| US-05 | 我想确认修改没有破坏项目 | 必需的编译、测试和静态检查均有明确结果 |
| US-06 | 我想知道失败发生在哪里 | Trace 能定位步骤、工具输入摘要、输出摘要和错误 |
| US-07 | 我想比较策略与模型 | 同一 Eval 可重复运行并汇总成功率、成本和时长 |
| US-08 | 我想从其他 Agent 客户端复用工具 | MCP 客户端可发现并调用允许的项目/构建工具 |

## 8. 非功能需求

### 安全

- 路径穿越、符号链接逃逸和 worktree 外写入必须被拒绝。
- 命令必须有超时、输出上限、工作目录限制和进程树清理。
- 高风险动作必须有可配置审批策略和审计记录。

### 可恢复性

- 每一步完成后保存状态；服务重启后可恢复到可判断的稳定状态。
- 工具操作应尽量幂等；不可幂等操作必须记录唯一执行 ID。

### 可扩展性

- LLM、Embedding、Vector Store、Sandbox、Tool 和 Trace Sink 使用接口隔离。
- 核心领域模型不得依赖具体模型厂商 SDK。

### 性能基线

- 10 万行以内示例项目的增量索引目标为 60 秒内（开发机基线待记录）。
- 非模型工具结果应在运行时提供进度，避免长任务无状态反馈。
- 上下文构建必须遵守配置的 Token 预算。

## 9. 成功指标

v0.1 发布门槛：

- 5 个基准任务中至少 4 个端到端成功。
- 基准任务编译成功率 ≥ 80%，测试通过率 ≥ 80%。
- 100% 的写入发生在隔离 worktree 内。
- 100% 的工具调用存在 Trace 和终止状态。
- 在禁用向量数据库时，核心演示仍可完成。
- README 中有可复现命令、示例报告和演示 GIF/录屏。

以上是首个基线目标，不作为长期质量承诺；每次发布应公布实际环境、模型和数据集。

## 10. v0.1 非目标

- 多 Agent 协作或角色扮演式 Planner/Developer/Tester 集群。
- 自动合并到用户分支、自动推送远程仓库或创建 Pull Request。
- COBOL 到 Java 自动翻译。
- Java 8 到 Java 21 全自动升级。
- Kubernetes 调度、云端多租户、企业 SSO。
- Jira、Jenkins、IDE 插件。
- 模型训练或微调。
- 对 Gradle、Node、Python 项目的正式支持。

## 11. 风险与缓解

| 风险 | 影响 | 缓解方式 |
| --- | --- | --- |
| Agent 无休止重试 | 成本与时长失控 | 步骤、Token、费用、重试、时长多重预算 |
| 检索遗漏关键代码 | 生成错误方案 | AST/BM25/图扩展组合；在报告中暴露检索证据 |
| 命令逃逸沙箱 | 破坏宿主环境 | worktree + Docker + 白名单 + 无网络 + 路径校验 |
| 不同项目构建差异大 | 验证不稳定 | v0.1 只支持 Maven，并提供项目适配配置 |
| LLM 输出格式不稳定 | Runtime 解析失败 | Structured Output、Schema 校验、有限次纠正 |
| Eval 被特定 Demo 过拟合 | 指标失真 | 多类任务、固定基线、公开任务定义和运行环境 |
| 过早做 UI | 延迟核心能力 | v0.1 以 CLI/API/Markdown 报告为主，Dashboard 延后 |

## 12. 发布物

- 可运行的 CLI 和 Spring Boot API。
- Banking Demo 或等价 Spring Boot 示例项目。
- 至少 5 个 Eval 任务及基线结果。
- 示例任务的 Markdown/JSON 验证报告。
- 最小 MCP Server 和客户端调用示例。
- Docker Compose 本地运行方式。
- README 演示 GIF/录屏和完整复现步骤。
